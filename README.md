# 轻衡 Qingheng

轻衡是一个面向家庭成员和朋友的中文体重管理 Web Demo。它把早晚体重、饮食、运动、睡眠、饮水和生活事件放在同一条时间线上，并据此生成 BMI、能量收支、趋势预测和 AI 日报。

项目采用手机优先设计，也适配桌面端；无需注册即可在浏览器本地使用。配置 D1 或腾讯云 CloudBase 后，可启用账号和跨设备同步。

> 健康计算和 AI 分析仅用于生活方式记录与趋势参考，不构成医疗诊断、治疗或减重处方。儿童、孕期、产后、老年人及患病用户应优先咨询医生或营养师。

## 项目能做什么

- 为多位家庭成员分别建立健康档案，记录早晚体重。
- 支持公斤和斤，内部统一换算为公斤计算。
- 记录早餐、午餐、晚餐、加餐和婴幼儿喂养。
- 内置 154 种常见食物，并支持添加自定义食物热量。
- 记录睡眠、饮水、高盐饮食、经期、旅行、生病和聚餐等背景信息。
- 记录 10 类常见运动，并按年龄、体重、时长和 MET 估算消耗。
- 生成成人 BMI、基础代谢、日消耗、体脂参考和能量收支。
- 为儿童和青少年提供 WHO BMI 年龄别 Z 分数参考。
- 为孕期用户提供基于孕前 BMI、孕周和胎儿数量的增重范围参考。
- 展示 7 日均重、14 日周期和短期体重趋势预测。
- 提供本地规则分析、DeepSeek、千问以及“复制提示词到官网分析”四种方式。
- 支持 CSV 明细导出和 JSON 完整备份。
- 支持 PWA 安装、响应式导航和离线友好的本地数据保存。

## 快速安装和运行

### 1. 环境要求

- Node.js `22.13.0` 或更高版本
- pnpm（项目只使用 pnpm，不建议改用 npm 或 yarn）
- Git

### 2. 获取代码

```bash
git clone https://github.com/GloriaMarian/git.git
cd git
```

如果尚未安装 pnpm，可先启用 Node.js 自带的 Corepack：

```bash
corepack enable
corepack prepare pnpm@9 --activate
```

### 3. 安装依赖

```bash
pnpm install --frozen-lockfile
```

### 4. 启动开发服务器

```bash
pnpm dev
```

浏览器打开：

```text
http://localhost:3000
```

首次使用可以直接选择游客模式。游客模式不需要数据库或账号配置，数据保存在当前浏览器的 IndexedDB 中。

### 5. 构建和本地预览

```bash
pnpm build
pnpm start
```

## 基本使用流程

1. 创建一位家庭成员，填写出生日期、性别、身高、人生阶段和目标。
2. 在“今日”页记录早晨和晚上的体重。
3. 记录当天饮食、运动、睡眠、饮水和特殊事件。
4. 查看当日指标、7 日均重、历史趋势和预测。
5. 在 AI 分析模块选择本地规则、自己的 DeepSeek/千问 API Key，或复制提示词到 AI 官网。
6. 定期导出 JSON 作为完整备份；需要表格分析时导出 CSV。

## 输入条件

下面的“程序校验”是当前 Demo 真实执行的限制。“使用建议”用于说明怎样输入才能得到有意义的结果；其中一部分尚未被程序强制校验。

### 成员档案

| 输入项 | 程序当前接收条件 | 使用建议与影响 |
| --- | --- | --- |
| 昵称 | 必填，去除首尾空格后不能为空 | 云同步时最多保留 40 个字符；建议每位成员使用不同昵称 |
| 出生日期 | 必填 | 必须是真实日期；年龄会影响儿童 Z 分数、成人指标和运动消耗 |
| 性别 | `female` 或 `male` | 用于基础代谢、体脂参考和部分青少年运动估算 |
| 身高 | 数字，当前未设置严格上下限 | 必须输入大于 0 的真实厘米数；错误身高会让 BMI、基础代谢等结果失真 |
| 显示单位 | `kg` 或 `jin` | `1 kg = 2 斤`；内部计算统一使用 kg |
| 人生阶段 | 婴幼儿、儿童、青少年、成人、老年、孕期或产后 | 阶段会改变指标展示和安全提示；孕期不会给出普通减脂建议 |
| 活动水平 | 久坐、轻度、中度或活跃 | 用于成人日消耗估算；儿童、青少年和孕期不使用普通成人活动系数 |
| 目标 | 维持、减重、增重、成长或孕期管理 | 用于界面和分析语境，不等于医疗目标 |
| 预产期 | 孕期档案可填 | 缺失时不生成孕周和孕期增重范围 |
| 孕前体重 | 孕期档案可填 | 必须为合理的正数；缺失时不生成孕前 BMI 与孕期范围 |
| 胎儿数量 | 1 或 2 | 用于区分单胎和双胎增重参考 |

### 每日体重

| 条件 | 说明 |
| --- | --- |
| 数值 | 必须为数字且大于 0；输入控件步长为 `0.1` |
| 单位 | 按成员档案选择 kg 或斤，保存时换算为 kg 并保留两位小数 |
| 时段 | 每天分为早晨和晚上两个时段 |
| 重复提交 | 同一成员、同一天、同一时段再次保存会覆盖原记录 |
| 日均体重 | 当天存在一条或两条记录时，取当天所有体重记录的平均值 |

### 饮食

| 输入项 | 程序当前接收条件 | 计算方式 |
| --- | --- | --- |
| 餐次 | 早餐、午餐、晚餐、加餐；婴幼儿可使用喂养 | 用于当天膳食完整度判断 |
| 食物名称 | 去除首尾空格后不能为空 | 可选内置食物或输入自定义名称 |
| 克数 | 当前要求为非零数字 | 应输入大于 0 的真实克数；负数尚未被 Demo 严格拦截 |
| 每 100 克热量 | 内置食物自动提供；自定义食物要求非零数字 | 应输入大于 0 的 kcal 值 |
| 单条热量 | 自动计算 | `克数 × 每 100 克热量 ÷ 100`，保留一位小数 |

首次保存的新食物名称会加入本地自定义食物列表。内置食物热量仅用于日常估算，不能代替包装营养标签或专业营养数据库。

### 运动

保存运动记录需要同时满足：

- 已选择成员；
- 该成员至少有一条体重记录；
- 年龄不低于 6 岁；
- 运动时长为有限数字，且大于 0、不超过 600 分钟；
- 从力量训练、瑜伽、跑步、爬坡、爬楼、游泳、跳绳、骑行、快走和健身操中选择一项。

运动输出包含活动名称、分钟数、采用的 MET、估算消耗、计算时使用的体重和所用标准。6 岁以下或缺少体重时不生成消耗估算，也不会保存该条记录。

### 睡眠、饮水和事件标签

- 睡眠输入单位为小时，饮水输入单位为毫升。
- 空值或 `0` 会被当作“没有记录”。
- 当前 Demo 尚未对睡眠和饮水设置严格上限，应输入真实、非负数值。
- 可选事件标签为：高盐饮食、经期、旅行、生病、聚餐。

### 账号输入

账号功能只有在服务端配置了 D1 或 CloudBase 后才可用；游客模式不受影响。

| 输入项 | 条件 |
| --- | --- |
| 用户名 | 3–20 个字符；允许中文、英文字母、数字和下划线；去除首尾空格并进行 NFKC 规范化；按小写形式判断唯一性 |
| 密码 | 8–72 个字符 |
| 确认密码 | 注册时必须与密码一致 |
| 登录限制 | 15 分钟内连续失败达到 8 次后，暂时限制 15 分钟 |

本项目不收集邮箱，也没有自动找回密码功能。忘记密码时，Demo 本身无法恢复账号。

## 输出条件和计算规则

### 核心指标

| 输出 | 生成条件 | 规则 |
| --- | --- | --- |
| 当日平均体重 | 当天至少有一条体重 | 当天早晚记录的算术平均值 |
| BMI | 当天有体重且身高大于 0 | `体重kg ÷ 身高m²` |
| 成人基础代谢 BMR | 年龄不低于 18 岁、不是孕期/产后/儿童阶段，且当天有体重 | Mifflin–St Jeor：`9.99×体重 + 6.25×身高 - 4.92×年龄 + 性别常数`；男性 `+5`，女性 `-161` |
| 成人日消耗 TDEE | 已生成 BMR 且有活动水平 | `BMR × 活动系数`；久坐 `1.2`、轻度 `1.375`、中度 `1.55`、活跃 `1.725` |
| 成人体脂参考 | 标准成人且已有 BMI | `1.2×BMI + 0.23×年龄 - 性别常数 - 5.4`；男性常数 `10.8`，女性为 `0`；界面提示约 ±4 个百分点误差 |
| 儿童 BMI Z 分数 | 年龄低于 18 岁，且有当天 BMI | 使用 WHO 0–5 岁和 5–19 岁 BMI 年龄别 LMS 参考表 |
| 孕期增重范围 | 孕期档案同时具有预产期、孕前体重和有效身高 | 根据孕前 BMI、当前孕周和单胎/双胎生成参考范围 |
| 当日摄入 | 当天至少一条饮食记录 | 当天所有饮食热量求和 |
| 当日运动消耗 | 当天至少一条运动记录 | 当天所有运动估算消耗求和 |
| 估算总消耗 | 已生成成人 BMR | `BMR × 1.2 + 当日运动消耗`，避免把已记录运动重复计入活动系数 |
| 能量差 | 已有估算总消耗且当天摄入大于 0 | `摄入 - 估算总消耗`；早餐、午餐、晚餐未全部记录时，界面不会给出完整方向性结论 |

特殊阶段的指标会优先显示安全提示，不应把普通成人的热量差、减脂方向或体脂判断直接用于儿童、孕期和产后用户。

### 儿童 Z 分数解释

- `Z < -3`：明显偏低；
- `-3 ≤ Z < -2`：偏低；
- `-2 ≤ Z ≤ 1`：参考范围；
- `1 < Z ≤ 2`：偏高；
- `Z > 2`：明显偏高。

该结果是群体参考位置，不是疾病诊断。

### 趋势和预测

| 输出 | 条件与含义 |
| --- | --- |
| 7 日均重 | 统计当天及之前 6 天中“有记录日期”的日均体重；不要求连续 7 天都有数据 |
| 14 日周期 | 从成员档案创建日期开始按 14 天划分，用于阶段性回顾 |
| 7 日预测 | 至少需要 7 条早晨体重；使用最近最多 30 条早晨数据、7 日滚动均值和最近最多 14 个平滑点计算线性趋势 |
| 预测限幅 | 日变化斜率被限制在 `±0.15 kg/天`，避免短期异常点产生夸张预测 |
| 预测输出 | 给出 7 天后预测体重、上下范围、预计每周变化和置信描述 |
| 置信描述 | 早晨体重达到 21 条时显示“较稳定”，否则显示“初步” |

预测是基于近期数据的数学外推，不代表未来一定达到该体重。

## AI 分析的输入和输出

### 支持方式

| 方式 | 是否需要 Key | 数据流向 |
| --- | --- | --- |
| 本地规则 | 否 | 仅在浏览器中根据已计算指标生成固定规则建议 |
| DeepSeek API | 用户自己的 Key | Key 随本次请求发送给本项目服务端，再转发到 DeepSeek 官方 API |
| 千问 API | 用户自己的 Key | Key 随本次请求发送给本项目服务端，再转发到允许的千问兼容接口 |
| AI 官网接力 | 否 | 复制系统生成的提示词，在 DeepSeek 或千问官网登录分析，再把 JSON 结果粘贴回来 |

用户 API Key 只保存在当前页面组件的内存中，不写入成员档案、IndexedDB、D1、CloudBase 或项目日志。刷新或关闭页面后需要重新输入。在线模型调用失败时会明确报错，不会悄悄替换成本地规则结果。

千问自定义地址必须使用 HTTPS，且主机属于以下范围：

- `dashscope.aliyuncs.com`
- `dashscope-intl.aliyuncs.com`
- `dashscope-us.aliyuncs.com`
- `*.maas.aliyuncs.com`

路径必须以 `/compatible-mode/v1` 或 `/chat/completions` 结尾。DeepSeek 使用官方 Chat Completions 接口。

### 发送给 AI 的健康摘要

系统只组合当前成员和所选日期的结构化摘要，主要包括：

- 日期、人生阶段和基础健康指标；
- 当天早晚体重；
- 餐次、食物名称和估算热量；
- 运动名称、时长、估算消耗和计算标准；
- 睡眠、饮水和事件标签；
- 近期趋势和程序本地生成的预测。

请不要在昵称、食物名称或粘贴内容中输入身份证号、手机号、住址、病历号等敏感个人信息。

### AI 返回格式

在线 API 或官网接力结果必须是一个 JSON 对象，也可以放在 Markdown 的 `json` 代码块中：

```json
{
  "summary": "",
  "weightReview": "",
  "nutritionReview": "",
  "lifestyleReview": "",
  "dataQuality": "",
  "prediction": "",
  "factors": [""],
  "actions": ["", "", "", "", ""],
  "safetyNote": ""
}
```

字段约束：

- `summary`、`weightReview`、`nutritionReview`、`lifestyleReview`、`dataQuality`、`prediction` 和 `safetyNote` 必须是字符串；
- `factors` 必须包含 1–6 个字符串；
- `actions` 必须恰好包含 5 个字符串；
- 结果必须是建议和风险提示，不能声称完成医学诊断；
- 儿童、孕期、产后等特殊阶段不得生成激进热量限制、减脂处方或体脂评价。

格式不完整或字段类型错误时，页面会拒绝导入并提示重新生成。医学安全要求通过提示词和页面告知约束模型，但当前 Demo 不具备自动识别所有不安全医学建议的能力，用户仍需自行判断。

## 本地数据、同步和导出

### 游客数据

- IndexedDB 数据库名：`qingheng-weight-journal`
- 对象仓库：`state`
- 当前状态键：`app-state-v1`
- 数据结构版本：`1`

游客数据只存在当前浏览器和当前设备中。清理浏览器站点数据、使用无痕窗口或更换设备都可能导致本地数据不可用，因此应定期导出 JSON 备份。

### 云同步

登录后，客户端以完整状态为单位与 D1 或 CloudBase 同步。D1 接口当前接受的单账号上限为：

| 数据类型 | 最大数量 |
| --- | ---: |
| 成员档案 | 30 |
| 体重记录 | 30,000 |
| 饮食记录 | 80,000 |
| 每日背景记录 | 20,000 |
| 运动记录 | 30,000 |
| 自定义食物 | 3,000 |
| AI 日报 | 10,000 |

单次同步请求的声明内容长度超过约 5 MB 时会被拒绝。服务端同步属于“提交完整状态”的 Demo 方案，不适合多个设备同时离线编辑后自动合并冲突。

### 导出格式

JSON 导出包含完整的 `AppState v1`，适合作为备份和迁移文件。

CSV 导出使用以下列：

```text
日期,成员,时段,体重kg,餐次,食物,克数,摄入热量kcal,运动,分钟,运动消耗kcal
```

CSV 适合在 Excel、WPS 或数据分析工具中查看明细，但不会完整保存档案设置、每日背景、自定义食物和 AI 日报，因此不能替代 JSON 备份。

## 当前 Demo 的限制

- 身高、饮食克数、食物热量、睡眠和饮水尚未全部设置合理范围校验；错误输入可能产生错误指标。
- 体重预测只使用近期早晨体重，是简单趋势模型，不考虑药物、疾病、水肿、月经周期或体成分变化。
- 食物热量和运动消耗都是估算值，不能代替营养标签、实验测量或专业设备。
- 账号没有邮箱验证和自动找回密码。
- 云同步采用完整状态覆盖，不提供复杂的多设备冲突合并。
- 在线 AI 依赖用户自己的第三方账号/API Key、网络连通性、额度和第三方服务条款。
- 仓库目前未附带开源许可证；在添加许可证前，默认不授予复制、修改或再发布权利。

## 隐私与安全

- 密码使用随机盐和 PBKDF2-SHA256 哈希保存，当前迭代次数为 100,000。
- 登录会话使用随机令牌和 `HttpOnly`、`SameSite=Lax` Cookie，默认有效期为 30 天。
- 不在仓库中保存用户 API Key、密码、Token 或私钥。
